Como adicionar um servidor ao cluster

Cada Raspberry Pi, tablet Android com ambiente Python compatível ou computador precisa executar o Worker do BotHub. Não basta conectar o dispositivo ao Wi-Fi.

1. Preparar o dispositivo
Instale Python 3.10 ou superior e pip. Mantenha o dispositivo ligado à internet. No Linux, instale também o suporte a ambientes virtuais (por exemplo, o pacote python3-venv no Debian/Ubuntu).
2. Criar uma conta Firebase para o worker
No Firebase Console do projeto BotHub, abra Authentication → Users e crie um usuário de e-mail e senha para este dispositivo. Use uma conta separada por worker; não compartilhe a senha de administrador.
3. Baixar e iniciar o Worker
No terminal do dispositivo, execute os comandos abaixo. Na primeira execução, o script configura o ambiente Python e pede um ID único para o dispositivo, o e-mail Firebase do worker e sua senha.
python3 -m pip install requests
curl -L https://raw.githubusercontent.com/daniblockss/Bot-advanced/main/bothub_firebase_worker.py -o bothub_firebase_worker.py
python3 bothub_firebase_worker.py
Escolha um ID simples e exclusivo, por exemplo raspberry-sala ou tablet-01. Não use o mesmo ID em duas máquinas.
4. Autorizar esse worker nas regras do Firebase
Depois de iniciar o worker uma vez, encontre o UID da conta dele em Authentication → Users. Em Realtime Database → Dados, adicione workerUids/ID_DO_DISPOSITIVO com o valor sendo o UID dessa conta (texto). Substitua ID_DO_DISPOSITIVO pelo ID digitado no terminal. As regras precisam continuar privadas; não abra leitura ou escrita para todos.
5. Confirmar no painel
Deixe o script rodando e aguarde cerca de 15–30 segundos. O dispositivo deverá aparecer em Dispositivos / workers com o nome do host e os recursos disponíveis. O BotHub pode então distribuir bots ativos para workers online com capacidade suficiente.

Se não aparecer, confira a saída do terminal, internet, credenciais Firebase e se o valor em workerUids/ID_DO_DISPOSITIVO corresponde ao UID correto. Para iniciar automaticamente após reiniciar, configure o worker como serviço do sistema no dispositivo.
